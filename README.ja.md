# vasp_util

[![en](https://img.shields.io/badge/lang-en-red.svg)](https://github.com/ohara-lab-su/vasp_util/blob/main/README.md)
[![ja](https://img.shields.io/badge/lang-ja-yellow.svg)](https://github.com/ohara-lab-su/vasp_util/blob/main/README.ja.md)

世の中に山のように存在する、VASPを便利に使うためのツールの一つです。

もともとは、[RMC-DFT](https://github.com/ohara-lab-su/rmc_dft/)
のパッケージ内で使用していたVASP関連のツール群を、
独立したライブラリとして切り出したものです。 (0.7.10 からブランチ)

ASE や pymatgen は、構造の生成・変換から各種解析まで幅広い機能を備えたライブラリです。
一方、VASP の入出力ファイルから構造を読み取り、必要な形式に変換して取り出すだけなら、
その部分を自前で実装することはそれほど難しくありません。
重要なのは、取り出した構造や計算結果に対して、どのような解析機能を用意するかだと考えています。

このため、構造の読み書きだけを目的に大きなライブラリへ依存するのではなく、
VASP の入出力操作を小さな独立した部品として整備し、
必要な解析処理を追加・再利用できるようにする方針を取っています。
もちろん、ASE や pymatgen が提供する高度な機能を置き換えることが目的ではありません。

## 開発の経緯

2010年頃から2015年頃にかけて、[sae](https://github.com/ohara-lab-su/sae)
という VASP を始めとした総合的な結晶構造関連のツールを開発していました。
当時蓄積したVASP関係のノウハウが、現在のツール群の基礎になっています。

ただ、sae は機能を追加するうちに巨大化してしまったことに加え、
当時の私自身のPythonに対する理解不足もあり、設計面でいろいろと問題を抱えていました。

さらに、気がつけば pymatgen や ASE が非常に便利になっており、
sae 自体の存在意義も薄れてしまったため、長いことお蔵入りになっていました。

とはいえ、その後もVASPを使ったツールを作っていると、
特にPOSCARに記述された構造をあれこれ操作するような場面で、
sae のようなものが欲しくなることが度々ありました。

そのたびに、個々のツールで似たような処理を実装してごまかしていたのですが、
結果的に同じようなコードがあちこちに増えてしまいました。

かといって、sae 全体を再設計するのは負担が大きいため、
まずは必要最小限の機能を持つ小さなライブラリとして、
RMC-DFT の内部で VASP 関連の処理を扱うクラス群を作成しました。

今回、それらを他のツールからも再利用しやすいように、独立したパッケージとして切り出したものが `vasp_util` です。

結果的には、世間にある同種のライブラリと似たようなものになってしまったかもしれませんが、
これまで個別のツールで繰り返し実装してきた処理を、少しずつこちらに集約していければと考えています。


## 現在の構成と対象範囲

現在は、POSCAR の格子・座標の読み取りと座標変換、周期境界条件下での原子間距離・近接原子・移動量の解析、INCAR・KPOINTS の編集、POTCAR の組み立て、OUTCAR のエネルギー・力・磁気モーメントの取得、VASP の実行・ログ管理などを扱います。

また、RMC-DFT から切り出した経緯から、RMC と VASP の構造データの受け渡しも対象にしています。現段階では、包括的な結晶構造解析環境を目指すのではなく、実際の計算・解析で必要になった機能を共通化していく方針です。

使用例と API の詳細は [ドキュメント](https://ohara-lab-su.github.io/vasp_util/) を参照してください。


## 実装 API とマニュアル

現在の実装について、各クラスの全メソッド・トップレベル関数をソースから確認し、[使用マニュアル](https://ohara-lab-su.github.io/vasp_util/jp/usage.html) と [API Reference](https://ohara-lab-su.github.io/vasp_util/jp/api_reference.html) を整備しました。API Reference はモジュール別の解説と Sphinx autodoc によるシグネチャ・docstring の自動表示を併用します。

依存関係については、独自の構造・解析機能を持つ一方で、既存実装には ASE および pymatgen を使用する箇所もあります。「一切使わない」という説明ではありません。


### API の網羅性と更新方法

`docs/api_reference.md` から、今回提供された10ソースファイルのクラス・メソッド・関数を全件確認できます。各項目には実装のシグネチャと既存 docstring に加え、戻り値式・条件分岐・例外・呼び出し先・ソース行を掲載しています。`docs/generate_api.py` によって再生成できます。実装からの静的抽出と実行時の動作保証は区別しています。
